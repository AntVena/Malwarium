WHAT THIS DOES

Writes a complete, working Malwarium onto the board through the USB-C cable — bootloader, partition table and firmware, all four pieces, straight from this page. No PlatformIO, no Python, no command line.

⚑ MOST UPDATES DON'T NEED THIS The device updates itself over Wi-Fi from CFG → UPDATES. Use the cable when the release notes say to, when the device won't boot, or when you're setting up a brand-new board.
⚑ YOUR PET SURVIVES A normal flash leaves the save partition alone, so your creature, Bits and 'Pedia progress are still there when it reboots. Only the erase option at the bottom wipes them.

BEFORE YOU START

  1. Use a data cable
    Plenty of USB-C cables only carry power. If the device never shows up in the picker, a charge-only cable is the first thing to suspect.
  2. Unplug the device
    All the way out. If it's running on a battery, that's fine — leave it be, the next step still works.
  3. Hold A, then plug it in
    Press and hold the leftmost button — A, the one you normally press for Next — and keep holding it while you push the cable in. Count to two, then let go.

    The screen will stay dark. That is exactly right. A holds the chip in its download mode, where it listens to the cable instead of running the game. It's the one step that makes this work every time, so do it even when you think you don't need to.
  4. Press FLASH and pick the device
    Chrome asks which USB device to talk to. Pick the one named USB JTAG/serial debug unit (or ESP32-S3) and choose Connect.

IF IT GOES WRONG


      

        The picker is empty, or the device isn't in the list
        

          
In order of how often it's the answer:

          
1. The cable doesn't carry data. Try another one — ideally the cable that
          came with a phone or a drive, not a charger-only one.

          
2. A didn't get held early enough. Unplug, press and hold A first, plug
          in second, then release. Holding it after the board has already booted does nothing.

          
3. The picker is filtered. Press MY DEVICE ISN'T LISTED above to show
          every serial device on the machine. On Windows the board reads as a COM port; on macOS
          and Linux it's a usbmodem / ttyACM device.

          
4. Something else has the port open. A serial monitor, the Arduino IDE, a
          PlatformIO terminal — close it and try again.

        

      


      

        “Failed to connect with the device”
        

          
The page found a port but the chip never answered. Almost always this is the board
          running the game instead of listening: unplug it, hold A, plug it back in, and
          press FLASH again.

          
If it keeps happening on a device that boots fine, try a different USB port —
          preferably one on the computer itself rather than a hub or a monitor.

        

      


      

        It flashed, but the screen stays dark
        

          
First, unplug and replug without holding A. A board left in download mode
          stays dark by design and will look identical to a failure.

          
If it's still dark after that, flash again with ERASE EVERYTHING FIRST ticked.
          That costs you the pet, but it clears a save or a stored setting that the new firmware
          can't read, which is the usual cause.

        

      


      

        What this writes, and where
        

          
Four images, at the four addresses the ESP32-S3 boots from — the same layout
          the project's own build writes over USB:

          
0x0000bootloader

          
0x8000partition table

          
0xE000OTA slot selector

          
0x10000firmware (app slot 0)

          
The save partition sits far above these and is never touched
          unless you ask for a full erase. The firmware image is checked against the SHA-256 the
          manifest publishes for it before a single byte reaches the chip — the same
          digest the device checks when it updates itself over Wi-Fi.

        

      


      

        Where the SD card fits in
        

          
It doesn't — not for this. The card holds the 'Pedia website the device serves
          over its own Wi-Fi, and nothing on this page reads or writes it. If the 'Pedia is what's
          out of date, the device updates that itself from CFG → UPDATES, or you can
          re-stage the card from the repo.
